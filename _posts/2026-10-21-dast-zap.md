Everything so far has been static: reading code, lockfiles, images, and infrastructure without running anything. **DAST** — Dynamic Application Security Testing — is the opposite. It deploys the application, browses and attacks it like a real user (or a real attacker), and watches how it responds. This is the layer where SAST is blind, and it is the natural next move in the lab.

## SAST vs DAST: complementary, not competing

- **SAST** reads source and finds *code* patterns. It sees a risky line even if it is never reached, but it cannot see runtime behaviour, server configuration, or logic bugs.
- **DAST** sends real requests and observes responses. It catches things SAST cannot: missing security headers, permissive CORS, insecure cookies, verbose errors, exposed endpoints, and authentication flaws.

The clearest example: an SQL injection that SAST flags in one file is verified by DAST firing a payload and watching the database error come back. One tool suspects; the other proves.

## Deploy a target

You need something running. Juice Shop is trivial to bring up:

```bash
docker run --rm -d -p 3000:3000 --name juice-shop bkimminich/juice-shop
```

Now it is live at `http://localhost:3000` and we have a legal target we own.

> **Scope and ethics:** only DAST a system you own or have **written authorization** to test. Active scanning sends attack traffic; against someone else's site it is unauthorized access. "I was just scanning" is not a defence.

## The baseline scan

OWASP ZAP ships a baseline that crawls the app passively and reports obvious issues without hammering it — safe enough to run on every build:

```bash
docker run --rm -t ghcr.io/zaproxy/zaproxy:stable \
  zap-baseline.py -t http://host.docker.internal:3000 -r report.html
```

`zap-baseline.py` spiders the site, applies a set of passive rules, and exits non-zero if it finds issues at or above a threshold. That exit code is what makes it a CI gate.

## Authenticated scanning: the part everyone forgets

The most valuable parts of an app live **behind the login**. A scan that only sees the public site misses the dashboard, the API, the admin panel — usually where the bugs are. ZAP handles this with a **context** that defines a login URL, credentials, and a verification for "am I logged in?", then **users** that reuse the session.

You describe it in the automation framework (`zap.yaml`) and run:

```bash
docker run --rm -t -v "$PWD:/zap/wrk:rw" ghcr.io/zaproxy/zaproxy:stable \
  zap.sh -cmd -autorun /zap/wrk/zap.yaml
```

Getting authentication right is the difference between a scan that finds real bugs and one that produces a clean report for a site it never actually entered.

## Scanning an API

If your app is an API (or has one), point ZAP at the spec:

```bash
docker run --rm -t ghcr.io/zaproxy/zaproxy:stable \
  zap-api-scan.py -t openapi.json -f openapi
```

It imports the endpoints from OpenAPI and attacks each one — far more thorough than guessing routes by crawling.

## Reading the report (and the false positives)

DAST is noisy by nature; it guesses. Expect false positives and triage them rather than trusting the count:

- A "missing header" may be set by a reverse proxy, not the app.
- A "possible SQL injection" is a suspicion until you reproduce it.
- A "CSRF" finding may not apply to a token-based API.

Confirm each one manually. DAST gives you the *where*; you still own the *whether*.

## Wiring it into CI

ZAP has an official GitHub Action for the baseline:

```yaml
      - name: DAST (ZAP baseline)
        uses: zaproxy/action-baseline@v0.12.0
        with:
          target: "https://staging.example.com"
          fail_action: true
```

Because DAST needs a running target, it runs against a deployed **staging** environment — later in the pipeline than SAST and SCA. That is the right shape: static checks on the pull request, dynamic checks after deploy, before production.

## What I took away

- **SAST suspects, DAST proves.** Neither replaces the other.
- **Authentication is the whole game.** An unauthenticated scan checks the least important surface.
- **DAST is noisy, so triage is mandatory.** Reproduce before you report.
- **It belongs after deploy.** Static checks shift left; dynamic checks shift right — both are the same discipline.
